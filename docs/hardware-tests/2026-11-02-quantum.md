## Ground truth from Windows

PnP property `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2`, all devices:

| Node | Battery | Container |
|---|---|---|
| Quantum Hands-Free AG (`BTHENUM\{0000111E-…}`) | 90 | `{E0A20B59-90F9-5F47-9CFB-8A3F4CC203DB}` |
| Microsoft Modern Wireless Headset Hands-Free AG | 80 | `{9DE4D14D-89B1-51A0-8790-4CFB0FCD9857}` |

So the value lives on the **Hands-Free AG** node, as `OsBatteryFeature` assumes, and the container-ID lookup finds it.

## Bugs and discrepancies

### 1. Fixed: a device first seen without a battery level never got one

`WindowsDeviceSource.DiscoverAsync` cached each device by ID and skipped any it had already built. A device that Windows had no battery level for at first discovery (`OsBatteryFeature.CreateAsync` returned null) kept no battery feature forever, contradicting STATUS.md ("appears on the next Refresh") and docs/modules/battery.md.

Fix: a cached device with no features is disposed and rebuilt on the next discovery. Found by reading the code; not reproduced on this hardware (both headsets already had a stored level). No unit test: `WindowsDeviceSource` calls WinRT directly and the repo has no Windows-platform test project or seam for it; adding one would be a larger refactor than the fix.

### 2. Open: stale battery shown for a disconnected device

Windows keeps the last level (80) on the Hands-Free AG node after the headset disconnects. Settings hides it; Samaat shows **80%** on the device card and in the CLI. The capability row correctly says "Device disconnected", but the card's percentage and bar read as current. Suggest the device card dims or hides the percentage (or shows its age) when disconnected. This is a UI/Core presentation choice, so it is written up rather than changed here.
